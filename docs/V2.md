# v2 — the data-first rewrite

`plugin/plugin.v2.js` is a rewrite of the picker that removes the machinery v1
used to fight the app. It exists because v1's bug was structural, not local.

## What v1 did, and why it broke

v1 painted Desktop's CSS custom properties onto `document.documentElement`
itself, persisted by writing the app's own `localStorage` keys, and pushed the
pick to the gateway with `config.set`. None of that is wrong on its own, but it
all bypassed the one thing that owns theme state: Desktop's `ThemeProvider`.

`ThemeProvider` re-applies its React state on every dependency change
(`apps/desktop/src/themes/context.tsx`). A manual paint therefore loses to it on
the next render, which is why the theme reverted on a navigation, a click, or a
profile switch. The gateway round-trip then re-applied a concrete variant
seconds later. The fix for v1 (see `fix/provider-sync`) hands the switch to the
provider — but the shape stays fragile.

## What v2 does instead

- **Registers the whole catalog as pure `THEMES_AREA` data.** No render, no
  apply, no state of ours. Every theme lands in the native Appearance picker and
  ⌘K automatically, exactly like a built-in.
- **Applies through `useTheme().setTheme` / `setMode`.** The app owns the paint,
  the per-profile persistence, and the mode.
- **Ships one control**, contributed to the end of the Appearance page
  (`APPEARANCE_AREAS.extra`): a searchable swatch grid and the TweakCN importer.

There is no manual repaint, no gateway sync, no `MutationObserver`, no custom
route, and no statusbar chip. Nothing in v2 writes theme state the app does not
own, so v1's revert bug cannot recur here.

## TweakCN import

[TweakCN](https://tweakcn.com) publishes presets as a shadcn registry:

```
https://tweakcn.com/r/themes/<name>.json     # one preset
https://tweakcn.com/r/themes/registry.json   # the index (42 presets)
```

A preset is a registry item whose `cssVars` carries `theme` (fonts, radius),
`light`, and `dark` colour groups. `tweakcnToDesktopTheme()` maps those onto
Hermes' `DesktopThemeColors`:

| TweakCN `cssVars.light` | `DesktopThemeColors` |
|---|---|
| `background`, `foreground` | `background`, `foreground` |
| `card`, `card-foreground` | `card`, `cardForeground` |
| `popover`, `popover-foreground` | `popover`, `popoverForeground` |
| `primary`, `primary-foreground` | `primary`, `primaryForeground` |
| `secondary`, `secondary-foreground` | `secondary`, `secondaryForeground` |
| `muted`, `muted-foreground` | `muted`, `mutedForeground` |
| `accent`, `accent-foreground` | `accent`, `accentForeground` |
| `border`, `input`, `ring` | `border`, `input`, `ring` |
| `destructive`, `destructive-foreground` | `destructive`, `destructiveForeground` |
| `sidebar`, `sidebar-border` | `sidebarBackground`, `sidebarBorder` |
| `cssVars.theme.font-sans` / `font-mono` | `typography.fontSans` / `fontMono` |
| `cssVars.dark` (whole group) | `darkColors` |

**Colour format.** shadcn writes colours as `oklch(L C H)`; Hermes' colour maths
is hex-only (`parseColor` rejects anything else). Every token is therefore
normalised to `#rrggbb` by `cssColorToHex()`, which handles `#rgb`/`#rrggbb`/
`#rrggbbaa`, `oklch()`, and `rgb()`/`rgba()`. The perceptual conversion is the
SDK's own `oklchToHex` — nothing is hand-rolled.

Imported themes are registered live via `THEMES_AREA` and written to
`hermes-desktop-user-themes-v1`, the key Desktop reads on the next boot's first
frame (the deterministic fix for upstream issue #71446).

A preset that would shadow a built-in desktop theme name is refused.

## Build

```bash
python scripts/regenerate.py --template plugin/plugin.v2.template.js --out plugin/plugin.v2.js
```

`--template` / `--out` are additions to the upstream generator; the default
invocation (`python scripts/regenerate.py`) is unchanged.

## Test

```bash
node --test tests/tweakcn-import.test.mjs
```

## Install

```bash
cp plugin/plugin.v2.js "$LOCALAPPDATA/hermes/desktop-plugins/theme-picker/plugin.js"
```

Then ⌘K → **Reload desktop plugins**. v1 and v2 share the plugin id, so
installing one replaces the other; swap back by copying `plugin/plugin.js`
instead.
